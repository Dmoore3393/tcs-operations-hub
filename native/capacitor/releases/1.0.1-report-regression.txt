USER-REPORTED SYMPTOM
A location licensee cannot correct or submit opening/closing reports after installing the released iPhone app. No screenshot, exact error, or device reproduction was available during this investigation. Do not describe this as resolved on the installed app.

EVIDENCE
- Read-only account/permission checks found the affected profile active with report-writing permission for its assigned location. No account permissions were changed. A permission-helper result is not a full signed-in end-to-end test.
- Source history shows the staff selection/signing fix in commit 877da71c5468aaba521758720b6913b40c8c998e (November 4 Pacific), and the report-type correction UI in 8cfb499fb763d296aa9bed836b7f034f559a4132 (November 8). Both are included in this release branch. The previously documented submitted iOS build predates these changes; the installed binary has not been inspected in this investigation.
- The earlier report screen uses asynchronous collection synchronization and displays a submitted message without awaiting persistence. The current source uses create_shift_report_with_staff, awaits its response, preserves the form on failure, and reloads report history after success. Do not re-enable broad collection writes or relax row-level security to accommodate the old screen.
- The native API adapter still targeted https://tcs-operations-hub.vercel.app. Project inspection confirmed Vercel Authentication is enabled for all_except_custom_domains. The established production domain thetcshub.com belongs to the same project. Requests to the hosting alias can encounter deployment authentication instead of the application API. This is an identified configuration problem, not proof that it caused every reported submission failure.

CHANGE SAVED TO THIS RELEASE BRANCH
src/lib/native-api.ts now sends the existing same-origin native /api/ requests to https://thetcshub.com. Existing path scoping, bearer headers, bodies, and caller authorization are unchanged. No deployment protections are disabled and no bypass credentials are embedded. Direct Supabase calls are unchanged.
